# Migrating from 0.3 to 1.0

1.0 replaces hand-written palettes with derived ones and removes every
duplicate spelling in one break. Most projects need a search-and-replace.

## Classes: variants move to attributes

| 0.3 | 1.0 |
|---|---|
| `class="ml-button ml-button-primary"` | `class="ml-button" data-variant="primary"` |
| `ml-button-secondary`, `-outline`, `-link` | `data-variant="secondary"` … |
| `ml-button-ghost`, `variant="ghost"` (Button, Input, Property Picker) | `data-variant="subtle"` |
| `ml-button-danger`, `ml-button-destructive` | `data-variant="destructive"` |
| `ml-button-sm`, `-lg`, `-icon` | `data-size="sm"`, `"lg"`, `"icon"` |
| `ml-badge-signal` | `data-tone="primary" data-variant="solid"` |
| `ml-badge-success` | `data-tone="success"` |
| `ml-card-interactive` | `data-interactive` |
| `ml-text-signal` | `ml-text-primary` |
| `ml-recipe-*`, `ml-intent-*` | the component class with `data-variant` |
| `ml-menu`, `ml-menu-item` | `ml-dropdown-menu`, `ml-dropdown-item` |
| `ml-check`, `ml-radio` | the Checkbox and RadioGroup components (`ml-checkbox-input`, `ml-radio-input`) |
| `ml-field`, `ml-overlay`, `ml-dialog` | `ml-input-field`, `ml-modal-overlay`, `ml-modal` |
| `ml-sidebar-layout`, `ml-container`, `ml-help`, `ml-error` | `ml-section-shell` / `ml-grid`, `ml-input-hint`, `ml-input-error` |

React components already emit the 1.0 markup.

## Tokens

| 0.3 | 1.0 |
|---|---|
| `--ml-signal` as a fill | `--ml-primary` |
| `--ml-signal` as text colour | `--ml-primary-text` |
| `--ml-signal-foreground`, `--ml-signal-fg` | `--ml-primary-foreground` |
| `--ml-signal-subtle` | `--ml-primary-subtle` |
| `--ml-bg`, `--ml-bg-subtle` | `--ml-background`, `--ml-background-subtle` |
| `--ml-border-focus` | `--ml-focus` |
| `--ml-danger` (etc.) as text colour | `--ml-danger-text` (etc.) |
| `--background`, `--foreground`, `--card`, `--chart-*`, `--sidebar-*` | the `--ml-*` token |

## Theme selection

`data-skin` is gone; use `data-theme`. The default theme is `graphite`.
`renderSpecCss(spec, { aliases })` now treats aliases as further
`data-theme` names for the same theme.

Explicit font stacks in a theme spec may only contain family names, quotes,
commas and `var(--token)`; anything else is dropped by `normalizeSpec` and
rejected by `validateSpec`, because stacks are written into stylesheets.

## Theme files

`mlola.theme.json` is now a theme spec. The 0.3 shape still reads:
`theme` is accepted for `vector`, and `colors.light.signal` /
`colors.dark.signal` become `color.primary` / `color.primaryDark`. Other
per-token colours are no longer taken, because the palette is derived and its
contrast guaranteed. Use `color.neutral` and `color.ink` to tint it, and
`extend` for anything the spec does not model.

## Themes look slightly different

Palettes are now solved for contrast, so a few colours moved: light-mode text
is darker, dark-mode primaries lighter, and bright brand colours keep their
fill while their text role darkens.

## Catalog blocks (commercial)

Every block now takes its content as typed props with believable defaults,
takes an `id` for its section anchor, and composes library components instead
of re-implementing them (`npm run check:composition` enforces this).

| Block | 0.3 | 1.0 |
|---|---|---|
| Navbar | `cta="…"`, `ctaHref="…"` | `cta={{ label, href }}` or `null`; `brand={{ name, mark, href }}` |
| HeroSplit | `accentWord`, `variant="with-visual"` | `accent`; variants `default` / `centered`; `visual` (node or `null`); `badge`/`secondaryCta` may be `null` |
| FeatureGrid | features `{ t, d, Icon }`, `sub`, fixed "View all components" link | `{ title, description, Icon }`, `description`, optional `cta` |
| PricingTiers | tiers `{ n, monthly, yearly, perMonthly, perYearly, desc, cta, hot, pts }`, `sub` | `{ name, price: { monthly, yearly }, period, description, cta: { label, href }, features, featured }`, `description`; only the featured tier gets the primary action |
| Testimonials | `initials` | initials come from `name`; optional `avatar`, `eyebrow`, `title` |
| FaqAccordion | fixed copy and contact card | `eyebrow`, `title`, `contact` |
| CtaFooter | fixed copy and footer | `title`, `description`, `finePrint`, `action`, `form`, `footer` (or `null`) |
| Newsletter | inline form | `form={{ placeholder, submitLabel, successMessage, onSubmit }}` |
| ProductGrid | fixed header | `eyebrow`, `title`, `description`, `showFilters`, `addLabel`, `formatPrice`, `productHref`, `onSelect` |
| StatsBand | stat `up` | stat `positive` (a falling churn rate is positive); `title`, `chart`, `chartLabel` |
| DataTable | row `initials` | initials come from `customer`; `action` link |
| AuthSplit | fixed copy, demo-only forms | `brand`, `title`, `panel`, `providers`, `onProvider`, `onLogin`, `onSignup`, link props; sign-up requires 8 characters. Handlers may be async: the form is busy while they run and shows the message of any error they throw. `forgotPassword`, `terms` and `privacy` accept `null` |

`ml-template-page` is now `ml-page-shell`, an engine primitive. Each block's
stylesheet sits beside it and is listed in its registry `files`.
